# Working preferences

Source: explicit user statements in the initial design conversation, 2026-10-16.
These are starting preferences, not claims inferred from unrelated history.

- Generally favor a loop of planning, independent plan review, implementation,
  independent output review, and resolving or proposing changes from findings.
  Do not enforce the full loop everywhere; use judgment about its value.
- Build a personal collection of skills that improves the quality of results
  over time. Poteto Mode / pstack is an inspiration, not an adopted rulebook.
- Use skills for instructions and access patterns, including existing MCP
  connections and APIs without MCP servers. Put repeatable deterministic work
  into shared CLI operations as needs become concrete.
- Keep the underlying knowledge format broad enough for both personal context
  and business-domain hubs spanning multiple repositories. Teams can contribute
  to Git-tracked hubs as they work with those systems.

A preference guides decisions. It does not by itself authorize publishing,
sending messages, purchasing, or accessing a new account.
