# Next increments

## Exercise the starting point

Use the working-methods hub on a real task. Check that an agent can find the
relevant instructions, apply review proportionately, and produce useful work.
Record concrete failures before adding more structure.

## Add one useful operation

Choose an actual service or local workflow. Describe its access route in the hub
and implement one deterministic operation with validated inputs and structured
outputs. Distinguish an agent's MCP connection from credentials or connections
available to the CLI. Keep adapters separate from domain knowledge.

## Reach it from the phone

Expose the proven operation through a remote MCP adapter. Choose authentication
and deployment deliberately, then add a private interactive page if the workflow
benefits from one. Keep live service state authoritative and define ownership of
any locally persisted state before adding writes.

## Improve working methods

Keep representative tasks and compare actual results as skills change. Use
independent evaluation when useful; do not force it on every minor edit. Treat
the fictional business hub as a check on generality, not a demand to connect work
systems to this personal deployment.

## Design references

- [pstack](https://github.com/cursor/plugins/tree/main/pstack): personal working methods composed from principles, playbooks, and skills.
- [Poteto Mode](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/SKILL.md): task routing and deliberate verification.
- [automate-me](https://github.com/cursor/plugins/blob/main/pstack/skills/automate-me/SKILL.md): capture the user's methods rather than adopting another person's rules wholesale.

These are inspiration, not installed dependencies or automatically adopted instructions.
